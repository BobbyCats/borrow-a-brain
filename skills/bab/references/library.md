# 专属素材库

素材库位于本套件数据目录的 `materials/`，与 Skill 代码分开。更新代码不删除素材。仅在用户要求收集、入库、保存素材，或已建立明确入库约定时复制；“帮我分析这个附件”本身不等于长期保存许可。已有授权覆盖时先生成预览并核对，再直接执行，不重复询问。

## 存放与版本

```text
用户数据目录/
├── state.json
└── materials/
    └── pdf/                         # 按材料分类
        └── 稳定编号/
            └── 项目取舍__编号前8位__r0002.pdf
```

索引记录标题、别名、分类、标签、原文件名、来源、内容日期（可未知）、导入与更新时间、revision、大小和 SHA-256。文件名由标题规范化，不让用户命名生成越界路径。

一个编号只保留当前文件。更新必须指定原编号，增加 revision，验证新内容后移除旧副本；原文件不动。没有长期版本备份，也没有自动回滚到旧文件的承诺。暂存与替换备份仅用于安全完成当前操作，成功后删除；清理失败明确报错并可重试。破坏性移动前写文件事务记录；中断后，确认旧进程已结束并处理写锁，后续写操作会按已提交状态恢复或完成清理。不要仅按写锁年龄删除。

相同范围内相同字节复用已有副本，保留别名和新的来源说明；不同项目不自动合并。相同字节不证明同一作者或同一事件，提炼时仍须核实。当前检索按标题、别名、原文件名、标签及类别筛选，不是全文或语义搜索。

## 导入与更新

由 Agent 准备参数，不要求用户填 JSON：

```json
{"source":"/用户明确提供的/会议纪要.pdf","title":"一月项目取舍会议","kind":"meeting","scope":"personal","tags":["项目取舍","会议"],"contentDate":"2026-01-05","sourceRef":"用户提供的会议纪要"}
```

1. `material-import 参数文件` 只预览，不复制。source 必须是指定的本地单文件。原始网址可放 sourceRef；文件由宿主已有工具在授权范围内取得，内核不下载、不解包、不扫描目录。
2. 核对来源、素材库位置、分类、大小、哈希、原版本和受影响记录。用户已要求入库且范围清楚时，这一步不要求再次确认。
3. 在同一参数中增加 `apply:true` 与本次返回的 `approvalHash`，再次执行。文件或原版本变化会拒绝，不能用旧预览强行覆盖。
4. 回读 `material-get 素材ID 范围`，确认实际路径、revision 和哈希。再用宿主文档、视觉或转写能力读取该副本。

更新在参数中加 `id`。重新导入一份不同内容但不提供旧 id 会创建另一项，因此用户说“更新这份”时必须先找已有编号；同名有歧义时只问区分项。默认单文件容量上限 2 GiB，可在已确认存储容量后用 maxBytes 调整。复制和哈希按流处理，不把大视频一次读入内存。

## 找回与使用

- `material-list 范围 [关键词] [分类]`：默认最多 20 项，按更新时间排序。精确项目 scope 从 context 获取。
- `material-get ID 范围 [revision]`：检查当前副本是否被直接改动并返回路径与 library 引用。指定旧 revision 时明确报旧副本已替换，不拿新版冒充旧版。
- 保存方法或个人记忆时，在 `source.material.library` 中保留返回的 `{id,revision,sha256}`。其他 material 字段仍记录页码／时间点、覆盖与身份。

先检索已收集素材，再让用户重复提供；找不到时如实说当前索引没有命中。材料不全时也不能扫其他项目或私人目录来补。

## 更新后旧方法怎么办

材料更换或删除后，旧版 record 与摘录保持原样，不能悄悄改成新版本号。读取时派生 `source-updated` 或 `source-missing`：

- 有旧来源的 active 方法退出自动目录；点名解析返回 needs-review。
- 已保存任务的 route-load 返回 needs-review，先复核来源再决定继续。
- 有旧来源的 confirmed 记忆不进入默认 memory-query；memory-list 仍能查看原因。

补读新版材料后创建新方法版本，试用并确认后启用。记忆需要用户确认修订。旧源文件不再保存，所以只能检查保留的必要摘录和定位摘要，不能宣称仍可重读旧全文。

## 删除与清理

`material-delete ID 参数文件` 先预览，参数含准确 scope。加 apply 与 approvalHash 后只删除受管理副本和索引。原文件、派生方法和必要摘录仍存在，相关引用会停止默认调用。不要把这称为“彻底忘记”。

用户要求彻底忘记时，先明确素材及其派生方法、记忆范围，再按现有 profile-delete / memory-forget 执行。`data-clear --confirmed` 清除全部派生数据和素材，包括已登记的清理残留，但不删除宿主原文件或已分享副本。

`material-cleanup` 仅重试已登记的失败备份和暂存清理，不扫描或删除任意相似命名目录。写锁异常先检查真实进程，不按文件年龄自行删除锁。
