# 自动选用与多人协作

用户不用先记住某个专家。自动路由是默认流程；明确点名、排除某人和“别再问、直接做”等当前指令优先。

执行下列命令前先读 [运行入口](operations.md#运行入口)。使用安装目录的 `scripts/run.mjs` 或 `bin/bab`，不要直接运行只导出函数的 `cli.mjs`。源码运行需 Node.js 22+。

## 两层选择

第一层选择工作流程：直接执行、提问、提炼别人、认识自己、使用帮助。第二层判断这次是否有合适的本地方法档案。写作、沟通和问答也可以使用人物方法，并不要求用户说“蒸馏”才触发。

1. 从当前要求和有效项目材料核对：**结果**（读者看完要理解、决定或做什么）、**读者与阶段**、**基准文件及依据版本**、**不可改变的约束**。短任务直接在当前上下文判断，不新增表单或持久记录。复杂任务只保留足以指导取舍的简短依据，执行和交付检查使用同一份。方法论的默认用途不能替换用户目的；例如展示能力以促成合作，不自动改成教听众完成练习。延续当前任务，不把补充信息当新任务。
2. 先确定本任务范围并查目录：默认采用宿主当前项目，运行 `route-context 项目路径`（仅命令工作目录确为当前项目时可省略路径）。只有用户明确要求个人范围，或宿主没有提供项目时，才运行 `route-context --personal`。一次返回规范化的 `scope` 和已启用的 `catalog`，不读取原始记录。后续查重、记忆检索、读取方法和保存分工均通过相应命令沿用这个 `scope`。项目目录包含个人方法与本项目方法，个人目录只含个人方法；路径无效时报错，不退回个人范围。
3. 由当前模型比较任务与这些说明。关键词只辅助检索，不构成路由算法。来源有限、明显不适用或只有名气相符时不要选。
4. 选 0–3 份方法。默认 0 或 1 份；目录命中不等于必须调用。只有第二份能补上具体判断或检查缺口才增加。短通知通常无需把结构、短句、常识核对拆成三个专家。多份必须有一个主责，其余有不重复的职责。能指出方法让哪个选择、句子或检查改变，才算增加价值；不向用户表演分工过程。
5. 用 `route-save` 记录本次分工和版本，再读取返回的精确版本。脚本检查范围、已启用状态、排除项与唯一主责；脚本不能代替模型判断语义适用性。
6. 执行后合成一个面向用户的结果。各视角分歧若影响用户选择，说明分歧的条件与推荐；不要简单多数投票。

多份材料冲突时，保留提出者、版本、确认状态和适用范围。当前明确要求优先；AI 建议、未确认提案和旧规则不能自动成为已确认要求。先查已有资料，只有仍会改变结果的缺口才提问。外部法规事实与项目决定分开核验。执行前后的检查都回到第 1 步的目标，不能只检查是否套全框架。

## 用户看到什么

例如用户说“帮我跟客户解释延期”。确有对应档案时可以选择：

- 老王的方法负责事实、责任和补救方案。
- 小李的方法检查语气与客户可能误解的地方。

按 [调用声明](disclosure.md) 显示实际入口、方法名称与精确版本，然后直接给可用文本。只有真正加载并使用的方法才显示为已应用。默认不表演一场专家群聊。

没有对应档案时正常完成任务，不编造不存在的专家。目录为空不妨碍从本次材料提炼方法；用户明确要留到下次使用时，进入 [建档到使用](people.md#建档到使用)，不能只解释目录结构。参数错误或查询失败不等于空目录，按错误信息修正后再判断。用户明确要求对照多个视角时可以展示独立意见，再给综合判断。

## 连续对话与成本

任务的 `excludedIds` 随 list/load 返回，同一任务改目标时继续保留；新增排除项合并。只有用户明确解除后，才传 `releaseExcludedIds` 与 `userApprovedExclusionChange: true`。空数组不会清除旧限制，不把任务排除扩大成永久禁用。

先区分原交付的续改与另一项交付。原目标、读者、范围和关键约束不变的缩短或改字，沿用本任务查询及精确版本；需要恢复时用 `route-load`，不重新挑选。换成另一项交付，或目标、读者、范围、关键约束及已知目录状态改变时，重新执行第 2 步，再判断适用性；上次的范围、空目录和“不适用”也只对原任务有效。新任务使用新 `taskId`；原任务改变条件仍保留原编号与排除项。用户叫停时停止本任务的方法协作。

重复保存相同分工不会清除已保存进度。目标、交付或方法改变后，旧摘要保留，但 route-load 返回 needs-review，checkpoint.needsReview 为 true。此时先核对原结果和下一步；已有保存授权覆盖时，用 route-checkpoint 更新核实后的进度，不能直接延用过时结论。

任务摘要只在确切范围内检索，项目重命名后不能扩大到全库。新会话找不到 taskId 时，先 `route-list 范围 [关键词]` 看最多 10 项轻量摘要。检索是文字筛选；用意图与交付内容判断匹配，多项同样合理时给具体区分项。选定后 `route-load` 恢复旧版本。没有记录就说明，不能拼造“上次”的决定。

用户要求下次继续，或已同意保留任务进度时，用 `route-checkpoint` 记录最小结果摘要与下一步。不要保存整段聊天。没有保存授权时只留本轮已有分工，不把用户的泛泛抱怨长期收录。恢复时检查事实是否仍有效，不自动发出旧草稿或重复执行已做动作。

默认由一个 Agent 顺序使用多份方法，普通宿主也能运行。只有宿主支持、用户授权且确有收益时才并行开子代理。选择了三份方法不等于真的启动了三个代理。

别让提问、专家选择、复盘和彩蛋挤占实际交付。默认一次最多三份方法，更多专家分阶段处理，并先解释增加的价值。
