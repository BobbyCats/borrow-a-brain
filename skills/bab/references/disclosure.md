# 调用声明

每条面向用户的回复只写一行；宿主已有格式时合并到其中，不另加页尾声明。只列本轮实际读取并使用的入口；已加载且仍有效的规则不必为声明重复读取。

没有宿主格式时用 `本次调用：Skill=…；方法=…。`。中文名可以和命令名并列。已有项目格式可以保留原有工具与流程字段，补入方法状态。

| 实际状态 | 方法字段 |
| --- | --- |
| 还未查询 | 待判断；不能提前宣称目录为空或选中某人 |
| 查到的目录为空 | 暂无可用的自定义方法（范围：个人通用 + 项目「实际项目名」）；个人查询只写“范围：个人通用” |
| 目录有方法但本题不适用 | 本次未选用（范围：实际查询范围；已有方法不适用） |
| 本轮从材料提炼新方法 | 本次提炼；已保存时说明草稿版本，不写已启用 |
| 主动提出收录建议，尚未确认 | 候选建议，未入库；不能算作已应用或已记住 |
| 已读取精确版本且用于本题 | 方法名称 + 版本；同任务复用可加“沿用” |
| 纯翻译、算术等直接完成 | 常规回答；没有实际用入口时 Skill 写未使用 |
| 查询失败 | 查询失败，说明是否按常规方式继续；不说没有方法 |

`route-save` 只证明分工已记录，不证明方法已执行。入口载入、目录查询、方法应用是不同事实。首次进度消息可写“待判断”，交付时按实际结果填写。多个专业 Skill 共用宿主的一行声明，不在可发送的邮件、通知或演讲正文里插入调用信息。

范围取自成功回执的 `scope` / `project`；项目用实际名称，不在普通声明中暴露完整本地路径。项目查询包含个人通用方法，不能把结果说成全机方法库为空，也不能据此判断有无未启用草稿或来源待复核的方法。没有可用的自定义方法时继续使用本次所需的内置流程；用户疑惑时简短解释，不每轮追加教学或收录提醒。

人物档案里的“说明方法与版本”也合并到这一行。不要修改历史档案来统一措辞。自动化的固定数据格式沿用宿主约定，不为声明破坏接口。
