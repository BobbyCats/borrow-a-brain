# 借用方法

把别人的经验变成用户能在新问题里使用的方法。

本流程负责两种任务：提炼新方法，以及使用已有方法。已有档案可由总入口自动选中，也可由用户点名。先读取 [人物档案](../people.md)；多人协作读取 [路由流程](../routing.md)。用户只想用已有方法时不要重新蒸馏。

## 从哪里开始

先确认用户要解决什么问题，再看材料。用户只有人物名字时，查可靠原始来源；无法查证就标注未知。用户不知道该学谁时，先按当前难题寻找适用的方法，不凭名气选人。

材料可能是文章、播客文字稿、视频字幕、公开案例或用户有权使用的私人资料。先区分完整来源、节选和转述。只取完成任务所需的部分。

## 提炼什么

每个方法都要写清：

1. 什么情境触发这个判断。
2. 他注意了哪些信号，忽略了什么。
3. 他在什么选项之间做取舍。
4. 最后做了什么动作。
5. 已知结果是什么；只是主张还是验证过。
6. 在哪些条件下不适用。

保留原始定位。区分“材料明确表达”与“AI 推断”。没有行动和结果的材料，只能产生待验证的方法，不能宣布蒸馏成功。

## 怎么交付

先用普通话交付一张方法卡：`遇到…… → 先看…… → 优先…… → 因为…… → 但如果……就换做……`。

再用用户的一个新问题试用。不要只复述原案例。检查是否给出了不同于泛泛建议的行动，以及有没有越过方法的适用范围。

用户希望复用时，输出可移植的 Skill：短入口、触发条件、判断步骤、输入输出、失败条件、来源说明、一条新问题测试。先保存在用户指定的草稿目录，不无声安装或覆盖同名 Skill。

产物命名为“从某材料提炼的方法”，不要冒充该人物本人。保留来源和许可要求，不复制受保护的全文。来自私人会话的方法默认私有，分享前重新检查材料与身份线索。
