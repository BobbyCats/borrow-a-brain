# 借用方法

把别人的经验变成用户能在新问题里使用的方法。

本流程负责两种任务：提炼新方法，以及使用已有方法。已有档案可由总入口自动选中，也可由用户点名。先读取 [人物档案](../people.md)；多人协作读取 [路由流程](../routing.md)。用户只想用已有方法时不要重新蒸馏。

## 从哪里开始

先确认用户要解决什么问题，再看材料。用户说素材已收集或上次已入库时，先按 [素材库](../library.md) 查当前范围，别让他重复上传。用户只有人物名字时，查可靠原始来源；无法查证就标注未知。用户不知道该学谁时，先按当前难题寻找适用的方法，不凭名气选人。

材料可以是原始视频、录音、文档、PDF、会议纪要、书籍页、图片或混合资料。先读 [材料接入](../materials.md)，复用宿主现有文件、转写、视觉或文档 Skill。不要要求用户先手工转文字。先给简短读取回执：实际读到的范围、归属与缺口。材料不支持的结论不提炼。

默认先围绕眼前问题提炼一招。只有用户要完整人物档案时才扩大调研。私下同事只用获准材料；不凭同名人物搜索结果拼出他的经历。公开人物补查一手来源的日期；旧材料不代表他今天仍持同样判断。

按需要查六类证据：长篇论述、被追问的回答、具体行动与结果、表达方式、反例或他者批评、观点变化的时间。已有材料够用就不补搜。保留冲突；不能为了让人物显得一致而抹掉例外。不设凑数的来源或模型数量。

## 提炼什么

每个方法都要写清：

1. 什么情境触发这个判断。
2. 他注意了哪些信号，忽略了什么。
3. 他在什么选项之间做取舍。
4. 最后做了什么动作。
5. 已知结果是什么；只是主张还是验证过。
6. 在哪些条件下不适用。

保留原始定位。区分“材料明确表达”与“AI 推断”。没有行动和结果的材料，只能产生待验证的方法，不能宣布蒸馏成功。

## 怎么交付

先用普通话交付一张方法卡：`遇到…… → 先看…… → 优先…… → 因为…… → 但如果……就换做……`。

再用用户的一个新问题试用。不要只复述原案例。先想没有该方法会怎样常规处理，再指出材料中的哪条条件导致一个不同选择或额外检查。没有差异就说明“这次方法未增加明显价值”，不为了展示调用而硬加步骤。检查有没有越过适用范围。

用户既说“想学这招”又要一段马上能用的文字时，交付顺序是：可用文字 → 两三句方法卡 → 材料能支持到哪里。明确区分材料中的动作和本次类推。成品不能代替学习结果。

想长期保存时，增加一个原材料有答案的校对题，再跑新问题和不适用问题。问“去掉人物名，这套方法还有哪些可辨识的选择？”若只剩“多沟通、看情况”，继续提炼具体条件。最多修订两轮；仍薄弱就保留草稿并写明缺口，不能填写虚构的 pass。

用户希望下次复用时，默认在当前确认范围建立方法草稿，审阅后启用。只有明确要求跨应用或分享时，才导出独立 Skill：短入口、触发条件、判断步骤、输入输出、失败条件、来源说明和试用记录。先预览导出全文，不无声安装或覆盖同名 Skill。

产物命名为“从某材料提炼的方法”，不要冒充该人物本人。保留来源和许可要求，不复制受保护的全文。来自私人会话的方法默认私有，分享前重新检查材料与身份线索。
