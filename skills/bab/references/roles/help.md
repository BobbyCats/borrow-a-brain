# 使用帮助

先判断用户卡在哪一步。不要把整本手册发给新手。

## 用户只需要会说一句话

| 用户可以直接说 | AI 应该做什么 |
| --- | --- |
| 我有个想法，你帮我看看靠不靠谱 | 找一个影响决定的关键问题，给推荐和理由 |
| 你别一下问这么多 | 缩成一个问题；能先做就先做 |
| 这篇文章挺厉害，我想学会他那一招 | 提炼有来源、能试用的方法 |
| 看看我最近老在纠结什么 | 先说明读取范围，再从获准记录找证据 |
| 我不喜欢你这样写，下次记住 | 规则明确且用户要求记住时直接保存；含糊时只澄清具体写法 |
| 这东西怎么用，你带我试一下 | 用当前小事体验一次，不先讲术语 |
| 你记了我什么 | 展示本套件的记忆、证据和状态 |
| 把这条忘了 | 定位并删除该规则的整个修订链 |
| 以后别给我推作者资料了 | 持久关闭资源推荐 |
| 你又理解错了 | 先修正当前问题；符合条件才建议反馈 |

这些是例子，不是固定口令。结合上下文识别意图。

## 三分钟上手

1. 有当前小事就直接带做。没有题材时，立即演示一个标明虚构的例子，例如把“图片呢？”改成有期限和可回答选项的催办消息；别先要求用户找题材或回复“用例子”。
2. 交付一个可用结果，简短指出材料中的哪一点改变了结果。需要用户选择时才问会改变下一步的问题，不对目标偏好硬凑推荐。
3. 邀请用户用自己的材料替换示例，不把虚构材料记成用户习惯。
4. 告诉用户，下次直接说自己的事即可。需要指定流程时再教一个命令。

不要一开始要求安装 Git、注册 GitHub 或提供长聊天记录。源代码运行与独立程序是两种分发方式；根据实际安装包教，不能把尚未发布的下载按钮说成可用。

## 怎么把材料交给 AI

收到“可以丢视频吗”“照片能用吗”“蒸馏自己要给什么”等问题，按 [素材指南](../../assets/materials-guide.md) 中对应类型教用户。先给一句可复制的说法和最少材料，不整本贴出。已经给了文件，就按 [材料接入](../materials.md) 先试读，不再要求用户重做输入。原片无法读取时，说明缺的是音轨、字幕还是画面，再提供最小替代办法。

用户想分类收集、覆盖旧版或随时找回时，按 [专属素材库](../library.md) 操作。用自然话说明库内当前副本、更新后旧方法待复核、删除范围。

## 遇到问题

- 找不到 Skill：检查安装目录、`SKILL.md` 格式、宿主刷新及新会话加载。不反复改用户全局规则。
- 无脚本运行能力：可做当前对话提问和材料分析；持久记忆、自动历史读取、更新脚本不可用。
- GitHub 不通：如作者已配置国内镜像，使用同版本签名包；否则用经过验证的离线包。不要编造已上线渠道。
- 版本更新：先运行检查，再用两三句话说明变化、影响和是否涉及环境。用户同意后执行。
- 用得不顺：先解决眼前问题。用户希望反馈时，读取 [反馈说明](../feedback.md)。

需要机器操作时读取 [操作说明](../operations.md)，需要更新时读取 [维护说明](../maintenance.md)。

包内 [三次上手练习](../../assets/getting-started.md) 提供完整的虚构材料、用户下一句话和完成标志。按用户眼前场景选一个，不要求按顺序学完。
