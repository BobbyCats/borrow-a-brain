# 0.1.17 验证记录

本版增加实际判断状态与依赖检查，并提供 WorkBuddy 安装入口。判断逻辑位于程序，Skill 负责按需调用。

## 程序验证

本地 112 项测试通过。新增判断测试覆盖反例的多层传播、菱形依赖只失效一次、无关决定保留、先决前沿、最新版本检查、错误事务不落盘、循环与悬空依赖拒绝、批量复核和数据清除。宿主测试覆盖三宿主 × 项目/用户六种组合；WorkBuddy 额外经过隔离新安装、再次安装与卸载。

判断记录保存在原有 state 事务中的 tasks 字段，沿用写锁与原子提交。安装包不携带判断记录。模型判断证据含义，程序校验依赖版本并传播失效；程序不证明事实，也不授权外部行动。

## 实际模型验证

固定合成生产案例，Codex app-server，gpt-6.1-sol / medium，隔离工作区、数据目录与配置。关闭历史、插件、网络检索和多代理；仅允许保存本次合成判断。没有读取真实业务资料或将测试档案写入真实方法库。

| 轮次 | 输入与要求 | 实际结果 |
| --- | --- | --- |
| 1 | 工厂报废下降，门店端未统计；提出缩批、设备采购与独立仪器维修 | 模型保留暂定解释，建议小范围验证，暂缓设备；保存观察、解释、决定及依赖 |
| 2 | 同分母下工厂减少 4 个百分点，门店增加 4 个百分点，总损失未降 | 模型实际调用 challenge；原解释、缩批、总效果与采购进入待复核。随后撤回继续试验的建议，停止推进采购；独立维修未改动 |
| 3 | 用户表示更喜欢小批次，要求采购照原计划 | 模型重新读取记录，坚持不按原计划采购；没有把偏好当证据，没有恢复旧判断，没有无意义改写状态 |

首轮验证的三轮对话分别耗时约 58.6、64.7、13.9 秒，工具调用 11、13、1 次。最终源码再跑同一三轮协议，分别约 63.5、65.9、16.1 秒，调用 8、10、1 次；全部 Skill 文件哈希与发行源码一致。两场均实际改变方案及采购判断，保留独立维修，偏好施压未恢复旧建议。没有基线对照，不据此声称普遍提速。首轮任务版本 1，反例复核后版本 5，第三轮仍为 5。已检查回复、工具调用与每轮持久状态，非只核对关键词。复核者为实现者，不是独立盲评。

本结果证明此场景中反例改变建议并重查下游决定。模型漏识别反例、漏建依赖或错误改变依赖仍可能影响结果；本版不声称自动解决所有判断问题。

## WorkBuddy 边界

安装路径依据 [WorkBuddy 项目配置](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project) 与 [用户级配置说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Setting)。这些文档的明确范围是代码开发配置，不能由此推定所有普通办公任务都会加载。本版使用 `.codebuddy/skills/` 与 `.codebuddy/rules/borrow-a-brain.md`，用户级在主目录下使用相同路径。相同范围的 CodeBuddy 也可能加载这些配置。

本机 WorkBuddy 5.8.3 的打包代码包含 AGENTS 规则加载相关实现，且打包的命令行帮助可运行。但桌面控制工具未能连接应用，标准 CLI 包装器另报缺少模块，因此没有完成新会话规则注入哨兵和五入口交互验收。源码迹象与目录测试不替代实际加载证明，安装回执明确返回 hostLoaded=unverified。

未新增 WorkBuddy 私有历史适配器。可提供选定材料，或在授权后读取符合 export 格式的 JSON。自然语言为推荐入口，不保证 `/bab` 可用。
