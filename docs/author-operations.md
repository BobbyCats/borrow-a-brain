# 作者端运行与分发

## 私有反馈服务

`server/feedback.mjs` 提供独立 API。首次运行需要在仓库外设置数据目录，并通过环境变量提供至少 32 字符的随机管理员令牌。

```sh
node server/feedback.mjs
```

环境变量：`BAB_INBOX_HOME`（必填）、`BAB_ADMIN_TOKEN`（必填）、`PORT`（可选，默认 8787）。服务只监听 127.0.0.1，生产需经 HTTPS 反向代理暴露收件路径。

| 接口 | 用途与权限 |
| --- | --- |
| POST /v1/feedback | 结构化收件；大小上限、来源限频、幂等编号 |
| GET /v1/feedback/:id | 需该报告的私有 Bearer 查询令牌；只返回状态和修复版本 |
| GET /admin/feedback | 需管理员 Bearer 令牌；返回私有收件清单 |

不要把管理员令牌放进分发包或网页源码。反向代理应限制请求大小与请求速率。服务不信任任意 X-Forwarded-For；使用代理时需要在代理层限流，否则后端看到的是代理地址。

`markResolved(home, id, version)` 是作者端模块函数，标记真实修复对应的版本。需要删除报告时由作者按本地维护操作处理；当前未提供公开删除或编辑接口。

当前没有连接生产网站，也没有管理页面。JSON 后台 API 已用回环请求验证；部署前需确定认证、备份、保留期限和官网集成方式。

## 可变地址

修改安装包内 `skills/bab/assets/author.json`，或让用户通过 `config-set` 保存本地覆盖配置。默认所有外部地址为空。

官网、反馈和更新入口分别配置，迁移不依赖服务器 IP。更新链必须保留一个长期入口或旧域名重定向；备用镜像和离线包作为第二条通路。不能承诺在所有旧入口都失效且用户离线时仍自动发现新地址。

## 签名更新

发行更新只包含 `skills/` 源代码。用户数据不进入包。作者私钥放仓库外，公钥随经过审阅的首个安装包分发。示例中不提供生产密钥。

```sh
node scripts/sign-release.mjs 私钥路径 公钥路径 更新说明文件 输出文件
```

脚本使用 Ed25519 签名，校验后才写包。主源、国内镜像和离线渠道分发同一签名文件。不要把私有 GitHub 访问令牌分发给现场用户。

发版步骤：更新 package.json 与 assets/version.json → 写用户可读的变化说明 → 测试和构建 → 签名 → 在试装目录执行升级及回退保护验收 → 上传到已确定的分发渠道 → 更新官网说明。

源码升级保留已登记的独立运行程序，运行程序动态读取新版脚本。若需要升级 Bun 内核，另发完整平台安装包并验证，不能把二进制升级伪装成普通方法更新。
