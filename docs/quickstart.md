# 使用指南

借个脑子提供 Codex、Claude Code 和 WorkBuddy 安装入口，需要本地文件读写与命令执行权限。WorkBuddy 的安装说明适用于代码开发项目。网页版聊天可体验材料分析；方法库、记忆管理和任务续接需要本地应用支持。

## 下载安装

从 [官网](https://jclab.work/tools/borrow-a-brain/) 下载并解压安装包。不需要 GitHub 账号。

| 你的设备 | 安装包 |
| --- | --- |
| Apple 芯片 Mac | `borrow-a-brain-mac-arm64.zip` |
| Intel / AMD 64 位 Windows | `borrow-a-brain-windows-x64.zip` |
| x64 Linux | `borrow-a-brain-linux-x64.zip` |
| 其他架构，或已安装 Node.js 22+ | `borrow-a-brain-source.zip` |

前三种安装包自带运行程序，无需额外安装 Node.js 或 Bun。通用源码包需要 Node.js 22+。不确定该选哪一种时，把官网安装说明交给当前应用，即可检查设备、选择安装包并准备运行环境。

在 Codex、Claude Code 或 WorkBuddy 中提供解压后的文件夹，输入：

> 帮我安装这个文件夹里的“借个脑子”。先检查环境，告诉我会装在哪里、改哪些文件，保留我原来的配置。装好后带我试一次。

安装默认用于你选定的项目。AI 会展示 Skill 目录、规则文件、数据位置和文件冲突，确认后再执行。检查环境不会读取聊天记录。

装好后，在该项目中开启新会话，输入：

> 我有件事拿不定主意，你帮我捋一捋。

回复中应显示实际调用的 Skill。若没有显示，按下方“常见问题”检查。

## 命令行安装

在当前安装包的解压目录或仓库根目录运行，将示例路径替换为一个已存在的项目目录。历史安装包使用其包内说明。

两种安装包共用启动器。以下以 macOS / Linux 为例：

```sh
sh "skills/bab/scripts/run.sh" setup codex "/absolute/path/to/project"
```

命令默认只生成安装预览。检查目录和规则后，加上 `--apply` 执行：

```sh
sh "skills/bab/scripts/run.sh" setup codex "/absolute/path/to/project" --apply
```

Claude Code 用户将 `codex` 换成 `claude`；WorkBuddy 用户换成 `workbuddy`。Windows 用户将项目路径换为 Windows 绝对路径，例如 `C:\Users\YourName\Documents\my-project`。

启动器自动使用包内程序，没有独立程序时检查 Node.js 22+。Windows 使用相同参数：

| 平台 | 命令入口 |
| --- | --- |
| macOS / Linux | `sh "skills/bab/scripts/run.sh"` |
| Windows PowerShell | `& ".\skills\bab\scripts\run.cmd"` |

安装位置如下：

| 应用 | 项目内 Skill 目录 | 项目内规则文件 |
| --- | --- | --- |
| Codex | `.agents/skills/` | `AGENTS.md` |
| Claude Code | `.claude/skills/` | `CLAUDE.md` |
| WorkBuddy | `.codebuddy/skills/` | `.codebuddy/rules/borrow-a-brain.md` |

要在所有项目中使用，将项目路径替换为 `--user`。这会改为用户级安装，执行前请核对预览。非标准安装路径及其他命令见 [本地操作](../skills/bab/references/operations.md)。

**WorkBuddy 使用范围**：按[官方项目配置](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)在代码开发项目中安装。用户级路径为 `~/.codebuddy/skills/` 与 `~/.codebuddy/rules/borrow-a-brain.md`，同范围 CodeBuddy 也可能加载。安装后新建项目任务，输入“用借个脑子帮我梳理”，检查回复中的调用声明。没有加载时，按下方常见问题检查规则与安装范围。普通办公任务不在当前支持范围内。

WorkBuddy 使用自然语言调用。分析历史时，提供选定的聊天片段或导出的 JSON；当前不直接读取 WorkBuddy 聊天数据库。

## 第一次使用

[三次上手练习](../skills/bab/assets/getting-started.md) 提供完整的示例材料，分别体验提问、提炼方法和个人偏好。也可以直接拿一件正在处理的事试用：

> 我准备给客户写一封延期说明，但不知道怎么开头。你先帮我理清要说什么。

安装包没有预装真人档案。你提供材料、试用并确认启用后，可以说“用这个方法再看一份新方案”。不点名时，AI 也会按任务选择已启用的方法。简单任务可以直接完成。

读取历史不是使用前提。需要分析旧对话时，再确认读取范围；需要保存偏好时，再确认具体条目。

## 视频、音频、PDF、书籍和照片怎么给

文件直接交给当前 AI 应用，或提供它能访问的链接。说清想学什么、用于什么问题即可。多人材料再说明谁是你。你不用先填写证据表或把所有文件转成文字。

> 这是访谈视频和几张书页照片。我想学他怎么决定先做什么，准备用来安排本周的任务。请标出实际读到的范围，用一个新问题试试，先不要保存。

详见 [素材提供指南](../skills/bab/assets/materials-guide.md)：包含视频、音频、PDF、书籍、办公文档、会议、图片和混合材料的具体示例，也说明蒸馏自己该提供什么。

分析结果会标明使用的页码或时间段，便于回查来源。字幕适合分析表达与判断；学习动作需要对应画面。缺少读取工具时，补充相关页、字幕或片段即可继续。多人材料请注明要分析的说话人。

## 把素材留下来，下次继续用

分析文件默认只用于眼前任务。想建立素材库时说：

> 把这份会议纪要收进我的素材库，标题叫“一月项目取舍会议”，标签是“项目取舍”，只用于当前项目。原文件别动。

AI 会先展示来源、保存位置和当前版本，再按你的要求执行。库内只保留一个当前副本；同范围内相同字节去重，来源说明保留。更新同一项时版本号增加，库内旧文件被替换，原文件不动。

> 找一下我之前收的项目取舍资料。这是它的新版，更新原来的素材，再检查之前的方法是否要改。

素材支持按标题、别名、原文件名、标签和类别查找，不含全文或语义搜索。来源更新后，依赖旧材料的方法与记忆会停止自动调用。复核新材料、试用并确认后再启用。

删除素材不等于删掉派生方法的所有摘录。要一起清除时，说明“把这份素材以及从它提炼的方法和记忆一起删除”，由 AI 先列出范围。

## 更新与反馈

正常使用时，本套件会请求当前应用检查新版。发现新版后展示更新说明，经你同意再安装；方法、记忆、素材、本地配置和原有规则保留。

- **检查频率**：成功检查后间隔七天，到期后再次使用时检查。
- **提醒次数**：同一新版自动提醒一次，没有后台推送。
- **立即检查**：说“立即检查借个脑子有没有更新，跳过检查间隔”。
- **没有收到提醒**：确认当前应用已加载本套件且允许联网。自动检查由应用执行，未执行检查就不会产生提醒。

网络失败不会中断任务。后续使用时按一小时、六小时、二十四小时的间隔重试，连续失败后最多每天重试一次。

输入“我想反馈一个问题”。AI 会整理问题、预期结果和复现步骤，展示正文与接收地址，确认后发送。源码仓库默认不配置作者服务；官网下载包包含更新和反馈配置。GitHub 自动生成的 Source code 压缩包是仓库快照，与作者提供的通用源码安装包不同。

提交后可以说“查一下刚才反馈的问题处理到哪了”。AI 使用该报告的私有回执查询状态和修复版本。平时的更新检查也会顺带查询已发送报告：每条成功查询间隔一天，每次最多三条，只在变化时提示。它不重新上传正文。作者标记已修复不等于用户问题已经解决；更新后应重试原来的问题。

## 数据管理

你可以直接提出这些要求：

- “你记了我什么？”——查看已保存的记忆。
- “这条只用于工作报告。”——限定偏好的适用范围。
- “这次别用老王的方法。”——跳过指定方法。
- “把这条忘掉。”——删除指定记忆及其修订记录。

数据保存在本机，和安装目录分开。实际位置可通过 `doctor` 查看。发给 AI 的材料仍按所用应用的数据处理规则处理。删除本套件记忆不会删除 AI 应用中的原聊天、已发送的反馈或已导出的副本。

## 常见问题

### 提示没有可用的自定义方法，还能用吗？

可以。提问、分析材料、提炼方法是安装后即可使用的流程。自定义方法是你另外收录的做法，保存草稿后还需确认启用。

有明确项目时，查询包含个人通用和当前项目的已启用方法，并注明项目名称。个人范围查询只包含个人通用方法。没有结果只说明这个范围暂时没有可选方法。未启用或来源待复核的方法不会参与选择；查询结果不能代表其他项目或未启用草稿的数量。

### 方法能在不同项目里用吗？

保存为“个人通用”的方法，可以在各项目中参与自动选择；保存为“项目专用”的方法，只用于指定项目。AI 会根据当前任务、方法的条件和边界判断是否选用。

新方法能跨项目复用时，AI 优先建议个人通用；依赖项目资料或约定时，建议项目专用。你确认后才保存，已有方法保持原范围。

方法集中保存在本机，无需复制到每个项目文件夹，也不要求先整理文件夹。没有明确项目时，可直接使用个人通用方法。安装位置和方法使用范围分别管理。要把已有项目方法用于其他项目，可以请 AI 先整理可通用的部分、展示来源与使用范围，再决定是否保存和启用。

**新会话没有调用 Skill。**

确认新会话位于安装时选择的项目。让 AI 检查 Skill 目录、同名冲突和规则加载情况，再按应用要求刷新或开启新会话。文件安装成功不代表应用已经加载。

**程序打不开。**

核对系统和处理器架构。不匹配时使用 Node.js 源码包。独立程序尚未完成 Apple 公证或 Windows 代码签名；不要通过关闭系统保护来安装。

**更新提示“本地有修改”。**

让 AI 显示差异，保留修改后再处理冲突。不要通过删除个人资料来重装。

**如何卸载？**

让 AI 使用原下载包执行 `uninstall`，目标为实际安装的 Skill 目录。卸载会移除本套件代码和规则，默认保留个人资料。需要清除资料时，请单独提出。Windows 必须使用下载包中的程序卸载，不能让已安装的程序删除自身。
