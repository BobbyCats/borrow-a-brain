# 0.1.7 本地验证

验证日期：2026-10-11。0.1.7 为本地开发候选，尚未发布安装包。

## 程序检查

- `npm test`：77 项通过，0 失败、0 跳过。
- `npm run validate`：5 个 Skill 的引用和脚本检查通过。
- `git diff --check`：通过。

本版增加主动收录入口的检查：

| 场景 | 结果 |
| --- | --- |
| 无数据目录时预览提议 | 返回内容与确认摘要，不创建数据目录 |
| 未明确确认或确认后改变内容、范围 | 拒绝保存 |
| 同一提议并发提交或重复提交 | 只产生一份草稿，重试回读真实文件 |
| 修订期间出现更新的基准版本 | 拒绝覆盖，要求重新回读和展示 |
| 保存为草稿 | 不进入自动选用目录，也不自动替换生效版本 |
| 写入版本失败 | 不登记空档案 |
| 索引提交后清理锁文件失败 | 保留已登记版本，报告清理错误；重试不重复创建 |
| 删除方法 | 一并删除版本及收录回执 |

独立代理使用虚构数据复查正常路径、并发和故障恢复。修复了查重命中草稿后可能直接使用的指令，以及提交后清理错误可能误删版本文件的问题。程序测试证明保存与状态约束，不能替代对话质量评估。

## 对话试用

全新上下文代理使用本机已安装入口，在隔离数据目录中执行四轮连续任务：

- 用户不提供方法名，代理根据任务选用适用的已启用方法，并回读精确版本。
- 普通消息改写中出现具体纠正后，先交付消息，再主动展示方法、范围、边界和推荐理由。候选未入库。
- 用户仅说“可以，再短一点”时，代理只修改成品，没有推断保存授权，也没有重复提议。
- 用户明确要求保存草稿、不要启用后，实际入库并回读 draft 与 activeVersion=null。

主代理回读完整输出，核对实际文件和目录状态。模拟数据未写入真实方法库。这是单个新代理的连续试用，不是四个独立窗口；也不是新手、其他模型或所有自然表达的通过保证。
