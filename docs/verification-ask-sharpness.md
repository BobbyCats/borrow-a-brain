# 提问取材与快速判断验证

日期：2026-10-17。基线为 0.1.15；候选修改聚焦分辨证据、停止取材、用户倾向与快速判断入口。材料均为合成，见 [固定输入](../tests/fixtures/ask-sharpness.json)。不使用真实用户聊天做公开测试材料。

## 条件与结论

同一声明模型 `gpt-6.1-sol`、medium，独立临时环境、空方法目录。冻结输入及两组 Skill 哈希，随机顺序运行三题、六场、十轮。实现者先阅读匿名输出并记录判断，再揭示映射；不是独立盲评。每条件仅运行一次，不能据此推算普遍成功率或保证提速。

初版候选在取材范围上有明确改善：生产题只读取索引和决定性记录，基线还读取无关会议与设备材料。纯倾向题更明确区分“先验证什么”和“原因已经成立”。基线同样没有把用户感觉当作证实，不能宣称修复了本对照中不存在的全面迎合失败。

| 场景 | 基线耗时 / 调用 | 初版候选耗时 / 调用 | 实际观察 |
| --- | --- | --- | --- |
| 有成交后，用户仅补充“感觉缺触达” · 两轮 | 47.49 秒 / 4 次 | 44.25 秒 / 6 次 | 两版都保留竞争解释；候选明确感觉不能证明原因，并回查付费与获客成本 |
| 工厂质检提速、交期变慢，随后补充分组反例 · 两轮 | 106.05 秒 / 8 次 | 97.14 秒 / 11 次 | 候选少读两份无关材料；两版都根据反例改查新品未决问题，保留总交期、退货与加班约束 |
| 只要对论证效果的直接感受 · 一轮 | 23.84 秒 / 5 次 | 25.85 秒 / 5 次 | 两版都能发现证据无法区分原因；候选没有更快 |

耗时为会话开始至结束的墙钟时间，含模型与工具等待。调用数包括本地工具和文件编辑，不等同于读取业务材料数量。生产题两版都触发方法候选预览；初版候选还因预览参数错误重试。两版均未写入方法库，只有临时参数文件变化。这些开销没有从报告中剔除。

## 依据结果做的修订

快速感受仍读取完整推导手册，因此在 `bab-ask` 入口增加直接路径：已有内容足够、用户只要感受时，检查决定性论据及竞争解释后直接答；需要核实的事实仍查，复杂推导仍读专项方法。未修改内核或放宽数据授权。

对同一快速题做一场定向回归：23.08 秒、3 次工具调用，输出 442 token。初版候选该题为 25.85 秒、5 次调用、530 token。新入口只读总入口、提问入口和方法目录，没有读取长流程。回答仍说明“有人付费”同时兼容两种原因，给出目标客户充分了解后的购买与持续使用表现作为分辨线索。

这支持“去掉了两次流程读取”，不支持显著或普遍的耗时提升。回归虽然使用相同声明模型与推理设置，宿主返回的上下文窗口上限与前一轮不同；时间数字仅记录本次运行。

## 保留的不足

- 工厂题两版第一句都偏早推荐调整终检排队；后文保留未决机制，分组证据出现后均修正。匿名评阅在这题更偏好基线的条件表达。
- 候选没有保证更少的总调用或输入 token。方法预览的开销仍存在，本次未扩大修改到收录机制。
- 新入口的速度收益只在单道感受题核查。真实业务中的分辨力、其他宿主与多轮稳定性仍须观察。
- 没有用更短、更大胆、用户认可或自评分代替业务效果证据。
