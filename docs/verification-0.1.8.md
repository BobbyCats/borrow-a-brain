# 0.1.8 验证记录

验证日期：2026-10-11。状态：发行候选，尚未发布。

## 改动

- `route-context` 一次返回规范化的项目范围与已启用方法目录。个人事务使用显式选项；无效路径不回退到个人范围。保留原查询接口和数据结构。
- 默认使用宿主当前项目，用户明确指定个人范围时切换。后续查重、读取和保存分工沿用同一范围，通过命令查询，不直接读取整库索引。
- 收拢任务切换和续改规则。主动收录先完成实际预览，再依次交付成品、方法卡、三个选项。补全收录参数帮助。
- 保存、摘要绑定、草稿、试用和确认启用的运行实现未修改。

## 程序验收

本机 84 项程序测试通过，0 失败、0 跳过。引用与脚本检查通过。源码和 macOS arm64 独立程序完成隔离安装、签名更新、重新启动、卸载与资料保留检查。

新增入口覆盖当前目录、显式项目、目录链接归一、个人范围、项目与个人混合目录、其他项目隔离、草稿过滤、无效路径、冲突参数、损坏状态与无写入查询。参数帮助仍使用包内同一份可执行草稿示例。

## 对话验收设计

使用真实 Codex app-server 的隔离新上下文。参考模型为 gpt-6.1-sol / medium，Luna / max 作补充。业务输入沿用此前合成题，不向模型提供评分标准。保留公开输出、实际命令、逐轮资料快照和失败记录；不读取隐藏推理或真实用户聊天。

分别检查：首次范围选择、精确启用版本读取、方法实际应用、查重、真实预览、正文与卡片顺序、三选项、含糊认可和拒绝后的无写入。显式保存分支只允许在用户确认后创建个人草稿，不能启用。

## 对话结果

最终候选的参考模型完成 **4 场、12 轮，4 场达到本轮目标**。

| 场景 | 实际结果 |
| --- | --- |
| 会议纠正与主动收录 | 项目范围查重和记忆检索；真实预览后交付正文、具体方法卡、三个选项和推荐理由；含糊认可只改稿，拒绝后不保存或重复建议 |
| 空目录后加入方法，再换任务 | 同任务续改沿用；换任务重查，实际读取启用的 v0002；首稿按方法顺序交付，不再次建议同义方法 |
| 明确的个人事务 | 仅个人范围查询；没有整库读取、文件枚举或项目方法读取；不写入资料 |
| 明确保存个人草稿 | 第一轮预览不保存；第二轮确认后只新增个人草稿，内容与原预览一致，未启用；已有档案、记忆和任务保持不变 |

同一候选的 Luna 补充测试完成 **3 场、8 轮**。规范范围命令正确、未直接读取整库状态、未未经确认保存或启用均为 3/3 场；换任务重查并读取精确版本为 1/1 场。以下项目未通过，不能称为全项通过：

- 一场个人事务在初次读取入口的同条命令中枚举了资料库的 11 条文件路径，包括其他项目档案路径。没有读取状态内容或项目方法正文，但不满足完整的访问隔离。
- 一场首次使用方法时，把原因放到选项前；下一轮纠正后才符合顺序。
- 一次普通缩短请求触发额外收录建议，该轮耗时约 240 秒。查重、预览和确认边界正确，但发现流程过重。

本批共 32 场、100 轮，包含被否决或修订的候选。各阶段分开判读，失败样本未被补跑替换；总数量不作为最终版本成功率。

| 候选 | 参考模型 | Luna | 判断 |

此前只移动原范围段落的对照没有达到采用门槛，见[范围位置对照](verification-scope-placement.md)。本批是固定题的小规模工程回归，未随机化，不能据此证明某句规则带来普遍因果改善。

参考模型承担主要验收，Luna 用于暴露额外问题。不会继续为一次输出偏差追加规则，也不把模型差异隐藏成“所有场景稳定”。访问约束依赖宿主遵循指令，Skill 文件本身不构成操作系统权限隔离。

## 验证边界

范围查询成功不等于方法完整应用。脚本约束范围、版本和确认摘要；宿主模型仍负责遵守读取边界和应用方法。小样本不证明所有表达、所有模型或新手体验均可靠。Windows/Linux 由 CI 验证运行链；真人宿主交互、操作系统代码签名和 macOS 公证另行验收。
