## 验证设计

参考模型为 gpt-6.1-sol / medium，Luna/max 作补充。全部使用合成材料、隔离 HOME/CODEX_HOME/BAB_HOME、独立模型上下文。保存公开回复、成功工具事件、故障入口审计和每轮资料快照，不读取隐藏推理，不将评分规则发给受试者。

分阶段冻结父版本、只改预览的版本、再改目录复用的版本：

1. 原会议题和扫描题：具体纠正后实际预览、正文后给候选与三选项；模糊认可和拒绝不保存。
2. 同一对话先写取消通知，再缩短，再切换成印刷排期消息，最后调整消息顺序。
3. 目录场景分别使用起初空库、第一轮后评测者加入人工方法，以及开聊前已有方法库。续改不重复查询；换任务重新查询并加载 v0002。
4. 预览故障仅注入隔离副本，其他命令保持原样。检查实际尝试、失败后的输出与无越权保存。

人工夹具包含相关启用 v0002、旧版 v0001、同义草稿、无关个人方法和另一项目方法。预置状态明确标注 FIXTURE ONLY，不是真实人物方法或真实试用成果。

| 场景 | 结果 |

| 组合修复，会议题 | 实际预览与提议通过；续改、拒绝不保存 |
| 最终预览措辞，会议题 | 实际预览、卡片、三个选项及确认边界通过 |

参考模型共 11 段、39 轮。首个故障样本保留为证据不足，不混入通过数。正常预览段全部逐轮资料哈希不变。路由段方法档案、记忆和启用版本不变，只有正常分工记录写入。

采集限制：第二个故障样本的入口审计确认命令被执行，但公开事件流仍未展开失败命令。因此不能仅凭第一个样本日志缺项，断言模型未执行。最终故障验收依据入口审计、最终回复和资料哈希三项，不伪称公开日志完整记录了失败命令。

父版本在本轮窄用例中也通过，不能计算修复提升率或证明某个字句单独有效。证据支持修复后的已测行为与确认边界成立；长期稳定性仍需后续实际使用。

## 发布判断与后续实验

这次是两处流程责任的合并，不是整套规则压缩。本轮父版本定向对照、故障注入与边界检查，比重跑全部五组更直接。当前不需要重新做整套 A–E 消融。
