# 借个脑子 · Borrow a Brain

**借别人的思路，理自己的难题。**

“借个脑子”是一套中文 AI Skills。它帮你学会别人的方法，整理自己的经验，也能在你想不清楚时，问到关键的地方。

当前是 **0.1.1 体验版**。五个入口、中文说明、国内安装包与私有反馈通道已接通。真实新手试用和宿主隐式路由仍待验收。详见 [当前状态](docs/status.md)。

## 你可以怎么说

```text
我有个想法，你帮我看看靠不靠谱。
这篇文章挺厉害，我想学会他那一招。
看看我最近的对话，找找我反复在意什么。
帮我写段话，跟客户解释这次为什么延期。
装好了，然后呢？你带我试一次。
```

不用先背命令。安装并让宿主加载路由规则后，AI 会结合当前任务选择流程。已有适用的人物方法时，也能自动选择并分工。

它会显示实际使用了什么。简单任务可以直接完成；没有合适的方法档案时，也能正常回答。

## 五个好叫的名字

| 名称 | Codex 手动调用 | 可以帮你做什么 |
| --- | --- | --- |
| 借个脑子 | `$bab` | 理解你要做什么，选择合适流程和方法 |
| 借个高手 | `$bab-pro` | 学别人的做事方法，保存下来，之后反复使用 |
| 懂我一点 | `$bab-me` | 从获准记录里认识你的习惯，形成可修改的记忆 |
| 问到点上 | `$bab-ask` | 一次问一个关键问题，给推荐，也讲清理由 |
| 带我上手 | `$bab-help` | 带你体验，处理安装、更新、反馈和数据管理 |

`bab` 是 Borrow a Brain 的缩写。不同应用的手动调用写法可能不同，自然语言入口保持一致。

## 学会一个人的方法，之后怎么用

以虚构人物“老王”为例。你提供获准使用的材料，让 AI 提炼他如何判断、怎么行动、什么时候换一种做法。

AI 会先生成草稿，用新问题试用，再请你确认。确认后成为你本地的一份方法档案。以后你可以说：

```text
用老王的办法看看这份方案。
```

也可以直接提出任务。AI 先看档案的专长和适用条件，按需选用。例如一份方法负责写清结构，另一份检查语气，最后给你一个完整结果。

每个人有独立目录和版本。你可以补材料、改错、回到旧版本或删除。需要给其他应用使用时，再审阅并导出独立 Skill。详见 [整体机制](docs/architecture.md)。

## 第一次使用

取得本仓库或作者提供的安装包后，可以对能操作本地文件的 Agent 说：

> 帮我安装这个目录里的“借个脑子”。先检查我的应用和运行环境，展示安装位置与路由规则。保留现有配置。

源码仓库保持私有。公开使用请前往 [官网说明与下载](https://jclab.top/tools/borrow-a-brain/)，演讲二维码也应指向这页。安装包已配置作者反馈与签名更新源；仓库的默认作者配置仍为空。

想先试而不安装，可以让 Agent 读取 `skills/bab/SKILL.md`，用当前对话体验提问或材料分析。这种方式不能保证下一次会话自动加载。

## 环境与数据

| 用法 | 要求 |
| --- | --- |
| 当前对话里提问、分析材料 | 能读取 Skill 指令的 AI 应用 |
| 自动发现并调用 | 宿主支持 Skill 与路由规则，并实际完成加载 |
| 本地记忆、历史读取、版本管理 | 文件与命令执行能力；用户同意相应范围 |
| 源码内核 | Node.js 22+；无 npm 第三方依赖 |
| 独立程序 | 对应平台的构建包；使用者不用安装 Node.js 或 Bun |

本机已构建 macOS arm64 开发程序。GitHub Actions 的 macOS、Windows、Linux 均已通过源码内核与独立程序的安装、升级和卸载验证。真实 AI 应用交互仍需逐个平台验收。

人物档案、个人记忆和授权保存在用户自己的数据目录，和代码分开。原始聊天不自动上传给作者。反馈先显示正文和收件地址，确认后才发送。

本地保存不代表模型完全离线。交给当前 AI 的片段仍按宿主的数据处理方式运行。

## 开发与验证

```sh
node bin/bab.mjs doctor
npm test
npm run validate
npm run build
```

最后一项只在构建独立程序时需要开发机安装 Bun。其余命令不需要安装 npm 依赖。
